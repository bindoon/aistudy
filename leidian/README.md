# 雷电风暴 · 小朋友学做游戏指南

这份文档根据一次真实的「边玩边改」聊天记录整理而成。  
思路很简单：**先做出能玩的小游戏 → 自己玩一遍 → 说出哪里不爽 → 再改一版**。  
下面的每一步，都可以当作给 AI（或老师）的提示词，一步一步把游戏做完整。

最终成品在本目录：`index.html` + `style.css` + `game.js` + `audio.js`。

---

## 怎么在本地玩

在仓库根目录 `games/` 下启动一个静态服务器，例如：

```bash
cd /Users/bouda/work/games
python3 -m http.server 8080
```

浏览器打开：

```text
http://localhost:8080/leidian/
```

操作提示：

| 操作 | 按键 / 方式 |
|------|-------------|
| 移动 | 方向键 / WASD / 触屏拖动 |
| 自动射击 | 游戏中自动开火 |
| 炸弹 | `空格` / `B` / `Z`，或点画布上的炸弹按钮 |
| 暂停 | `P` / `Esc` |
| 音效 | 点右上角「有声 / 静音」 |

## 项目文件（给小朋友看的结构）

```text
leidian/
├── index.html   ← 页面：标题、分数、生命、按钮、画布
├── style.css    ← 样子：颜色、布局、按钮长什么样
├── game.js      ← 大脑：飞机、敌人、子弹、关卡、碰撞
└── audio.js     ← 耳朵：射击声、爆炸声、背景音乐
```

记口诀：

1. **HTML** 摆桌子（有哪些按钮和画布）
2. **CSS** 刷油漆（好不好看）
3. **JS** 写规则（怎么动、怎么打、怎么加分）
4. **音频** 加气氛（好不好玩还要听）

## 教学总路线图

整次开发其实分两大阶段：

```text
阶段 A：接水果小游戏（练手：下落、接住、道具）
        ↓ 玩腻了，想换题材
阶段 B：改造成雷电打飞机（本目录最终游戏）
        ↓ 继续提需求
阶段 C：武器 / 声音 / 关卡 Boss / 复活 / 性能
```

下面按「真实提出的问题」编排成课。每一课都有：

- **当时的问题**（原话整理）
- **可以怎么问 AI**（提示词模板）
- **学到什么**（游戏设计 / 编程概念）
- **对应到哪里改**（方便对照代码）

## 阶段 A｜从零做一个接水果游戏

> 说明：接水果是最早的练手版。后面改成雷电后，逻辑仍值得学——  
> 「东西从上面掉下来 / 玩家左右移动 / 碰到加分或减命」。

### 第 1 课：先做出能玩的最小版本

**当时的问题**

> 我想玩接水果游戏。我现在要开发。

**可以怎么问**

```text
帮我做一个浏览器接水果小游戏：
- 篮子左右移动接水果
- 接到加分，漏掉或撞炸弹有惩罚
- 用 HTML + CSS + Canvas + JavaScript
- 先做出能玩的最小版本
```

**学到什么**

- 游戏循环：`更新位置 → 画出来 → 下一帧再来`
- 玩家、掉落物、碰撞检测这三个最基本零件

---

### 第 2 课：界面乱了，先整理画面

**当时的问题**

> 这个界面有点乱。帮我优化一下。

**可以怎么问**

```text
游戏已经能玩了，但界面很乱。
请整理 HUD（分数、生命、时间），让第一眼就知道在玩什么。
不要堆太多卡片和按钮。
```

**学到什么**

- 先保证「看得懂」，再加新功能
- 分数 / 生命 / 关卡要放在固定位置

---

### 第 3 课：节奏不对就调参数

**当时的问题**

> 时间太短了；炸弹不够多；有的掉得快、有的掉得慢。

**可以怎么问**

```text
请把一局时间调长一点。
炸弹出现再多一些。
掉落物速度不要都一样：有的快、有的慢，这样更有趣。
请告诉我改了哪些数字（比如时间、速度、生成间隔）。
```

**学到什么**

- 很多「好不好玩」只是在改数字：时间、速度、间隔、数量
- 先玩，再调，不要一开始就追求完美

---

### 第 4 课：规则要想清楚

**当时的问题**

> 漏掉水果不要减命，改成得分低一点。

**可以怎么问**

```text
把规则改成：
漏掉一个水果不减命，但会扣一点分（或减少连击）。
只有撞到炸弹才减命。
请同步改结束条件和提示文字。
```

**学到什么**

- 规则改变 = 代码里「什么时候扣命 / 加分」要一起改
- 设计游戏时，先用一句话说清输赢条件

---

### 第 5 课：一次加几种道具

**当时的问题**

> 加吸铁石（吸附近水果，不吸炸弹，持续约 30 秒）；  
> 加火箭（很快砸下来，要有预警）；  
> 加爱心（加命）。

**可以怎么问**

```text
请增加三种道具，每种都写清楚：
1）看起来长什么样
2）怎么出现
3）接到/撞到会发生什么
4）持续多久

道具：
- 吸铁石：吸附近水果进篮子，吸不到炸弹，约 30 秒消失
- 火箭：很快下落，屏幕上方要有危险提示，撞到减命
- 爱心：增加一条命
```

**学到什么**

- 描述道具时，用「外观 / 出现 / 效果 / 时间」四件套最清楚
- 危险物一定要给玩家反应时间（预警）

---

### 第 6 课：玩了之后再平衡难度

**当时的问题**

> 火箭太小太好躲；吃到流星要短暂加速，并带保护罩。

**可以怎么问**

```text
火箭碰撞体积再大一点，更难躲。
再加流星道具：吃到后约 3 秒移动变快，并有短暂保护罩。
```

**学到什么**

- 好玩 = 难一点，但还能躲开
- 「保护罩 / 加速」是常见的短时增益写法

---

## 阶段 B｜改造成雷电打飞机

### 第 7 课：题材大改造

**当时的问题**

> 我想改成雷电那种打飞机的游戏。随时可能有闪电，击中会减命。

**可以怎么问**

```text
把接水果改造成自上而下的雷电射击游戏：
- 玩家飞机在下方，自动向上射击
- 敌机从上方出现
- 随机闪电：有预警，击中减命
- 保留分数、生命、最高分
请先搭好能玩的框架，再慢慢加武器。
```

**学到什么**

- 题材变了，但零件很像：玩家、敌人、掉落/生成、碰撞、HUD
- 「预警再伤害」是公平设计

**代码对照**：`game.js` 里的玩家、敌人、闪电；`index.html` 标题与 HUD

---

### 第 8 课：多种子弹 + 升级

**当时的问题**

> 要有激光、散射等多种子弹；同一种吃多次升级，最多 5 级。

**可以怎么问**

```text
请做多种武器胶囊：激光、散射，再自由加 2～3 种。
规则：
- 同一武器吃多次可升级，最高 5 级
- 换成另一种武器时，新武器从 1 级重新开始
子弹外观要能一眼看出是哪种（参考魂斗罗老鹰胶囊，不同颜色）。
```

**学到什么**

- 数据驱动：武器表（名字、颜色、伤害、射法）
- 「换武器重置等级」要写进规则，不然玩家会觉得 bug

**代码对照**：`WEAPONS`、`weaponLevel`、`shoot*()`、老鹰胶囊绘制

---

### 第 9 课：按钮点了报错，学会修 bug

**当时的问题**

> 点击出击打不开；控制台报 `state is not defined`。

**可以怎么问**

```text
点「出击」没反应。控制台报错：
Uncaught ReferenceError: state is not defined
请找到 startGame 相关代码并修复，告诉我错在哪一行、为什么。
```

**学到什么**

- 打开浏览器开发者工具看红色报错
- 变量要在能用到的地方定义；作用域搞错最常见

---

## 阶段 C｜做成「像真正雷电」的完整游戏

### 第 10 课：加声音（还要会排查）

**当时的问题**

> 要加声音；点了右上角没反应；背景嗡嗡声太可怕。

**可以怎么问（分三步更好）**

```text
1）用 Web Audio 加射击、爆炸、吃道具、BGM；右上角做静音按钮。
2）静音按钮点了没声音：请检查 AudioContext 是否需要用户点击后解锁，按钮是否被挡住。
3）BGM 太阴森，改成轻松一点的短旋律。
```

**学到什么**

- 浏览器常规定：要先有一次点击，音频才能响
- 按钮「看不见 / 点不到」也是常见 bug
- 音效风格会影响恐惧感或轻松感

**代码对照**：`audio.js`、`index.html` 静音按钮、`style.css` HUD 布局

---

### 第 11 课：炸弹 + 关卡难度结构

**当时的问题**

> 加携带炸弹（效果像雷电）；同一关难度别陡增，关与关之间再变难。

**可以怎么问**

```text
1）玩家可携带炸弹：按键清空屏幕敌弹/伤害敌人，有冷却和数量上限。
2）难度不要在同一关里越来越猛；改成第 1 关稳定，第 2、3 关再提升速度和血量。
```

**学到什么**

- 「关内平稳、关间变难」比「越玩越疯」更适合小朋友
- 炸弹是「救命技能」，数量要够用但不能无限

**代码对照**：`STAGES`、`bombs`、炸弹特效与按键

---

### 第 12 课：武器手感 + Boss 闯关

**当时的问题**

> 紫色链弹太弱；后面子弹断粮；应该打一段时间后出现大怪兽，打完进下一关。

**可以怎么问**

```text
1）加强紫色链弹的伤害/跳跃次数，让它值得捡。
2）保证后期也能掉武器/道具，不要后面一个都没有。
3）每关流程改成：杂兵一段时间 → Boss 预警 → 打 Boss → 过关进下一关。
```

**学到什么**

- 流程状态机：`wave → bossWarn → boss → clear → 下一关`
- 掉落「怜悯机制」：太久没掉就强制掉一个，避免憋死

---

### 第 13 课：数学题复活（边玩边学）

**当时的问题**

> 死了后给复活机会，做连加连减题；可以复活 3 次。

**可以怎么问**

```text
玩家死亡后弹出小学数学题（连加或连减）。
答对复活，最多 3 次；答错或放弃则正式结束。
题目难度适合低年级。
```

**学到什么**

- 游戏可以掺一点学习目标
- 「次数上限」要写清楚，不然会无限复活

---

### 第 14 课：敌人也要会打人

**当时的问题**

> 怪兽没有攻击力不好玩；小怪子弹太密；Boss 要能打但别太狠；后来又说小怪疏一点、Boss 密一点。

**可以怎么问**

```text
请区分两类敌人开火：
- 普通小怪：子弹稀疏，给玩家空隙
- 关底 Boss：弹幕更密、花样更多，但仍要能躲
闪电预警加长，且尽量别和超密弹幕叠在一起。
```

**学到什么**

- 难度分层：杂兵练手，Boss 考验
- 「能躲」比「突然必死」更重要

---

### 第 15 课：关卡切换要干净

**当时的问题**

> 每个关卡最后有大 Boss；打过后子弹清掉再开下一关。  
> UI 里不要混英文单词；炸弹后面不够用，要多一点。

**可以怎么问**

```text
1）过关时清空敌我子弹和杂兵，再进入下一关介绍。
2）界面文字改成中文（炸弹/首领/级）。
3）开局炸弹多一点，上限高一点，关卡奖励也给炸弹。
```

**学到什么**

- 过场要「清场」，不然上一关子弹会误伤
- 给小朋友玩的界面，尽量全中文

---

### 第 16 课：弹射道具 + Boss 花式召唤

**当时的问题**

> 吃道具后子弹可弹射；炸弹再多一点；Boss 技能花哨一点，蛟龙要放小龙出来。

**可以怎么问**

```text
新增弹射道具：吃到后一段时间子弹碰墙反弹。
Boss 增加召唤技能：不同关召唤不同小怪（护卫机/风暴仔/雷球/小蛟龙/魂魄）。
炸弹数量再抬一点，但设置上限。
```

**学到什么**

- 新道具要想好：持续时间、上限、会不会卡顿
- Boss「召唤小怪」比单纯加血更有戏

**代码对照**：`bounceUntil`、`spawnBossMinions`、`UTILITY_DROPS`

---

### 第 17 课：修卡死、修卡顿（很重要的一课）

**当时的问题**

> 进第二关卡住，要暂停再恢复才好；弹射时游戏变卡。

**可以怎么问**

```text
1）第二关卡住：检查 gameLoop 是否有 return 后没继续 requestAnimationFrame；
   用 try/catch 保证一帧出错也不停掉循环。
2）弹射卡顿：子弹不要每帧重复打同一敌人；限制弹射子弹数量；
   减少撞墙粒子和音效频率。
```

**学到什么**

- 动画循环断了 = 画面假死
- 性能问题常常是「同一件事做太多次」（粒子、音效、碰撞）
- 先定位原因，再改，不要瞎加功能

---

### 第 18 课：关卡时长与召唤数量再微调

**当时的问题**

> 每一关太短，一下就碰到大怪兽；大怪兽召唤的小怪兽可以多一点。

**可以怎么问**

```text
把每关杂兵阶段时间大约加长到原来的 1.5 倍。
Boss 每次召唤小怪数量增加，场上召唤物上限也提高一点。
```

**学到什么**

- 手感微调是最后一公里：时间、数量、间隔
- 改 `waveFrames`、`spawnBossMinions` 的 `count`、`MAX_MINIONS` 这类常量即可

**代码对照**：`STAGES[].waveFrames`、`MAX_MINIONS`、召唤配置表

## 给小朋友的「提问公式」

不会写代码时，也可以按这个公式说需求：

```text
我想加【什么】。
它看起来【什么样】。
玩家怎么【得到/触发】它。
得到以后【发生什么】。
持续【多久】/ 最多【几个】。
如果和别的东西一起出现，【谁优先】。
```

修 bug 时这样说：

```text
我点了【什么】。
我期望【怎样】。
实际变成【怎样】。
控制台有没有红字（有的话粘贴出来）。
```

## 老师带做时的小提醒

1. **先玩再改**：每个功能做完立刻试玩，比一次写十个功能更有效。  
2. **一次只改一类事**：今天只加声音，明天只加 Boss，孩子不容易乱。  
3. **把「好玩」翻译成数字**：太难 → 子弹少一点 / 预警久一点 / 关卡久一点。  
4. **保留报错原文**：修 bug 时，红字比「打不开」有用一百倍。  
5. **鼓励自己设计一关**：改 `STAGES` 里的名字、血量、召唤类型，就是在做关卡设计。

## 下一步可以继续提的问题（作业）

孩子做完现有版本后，可以继续挑战：

```text
1）加一个双人轮流玩：每人一局比高分。
2）做一个商店：用得分换炸弹或护盾。
3）Boss 血条掉到一半时变身，换一套新弹幕。
4）加简单成就：连续不死 60 秒、用链弹击败 Boss 等。
5）把某一关改成自己的故事（自己的关名、自己的 Boss 表情）。
```

把上面任意一条，按「提问公式」写完整，再交给 AI 或自己实现即可。

## 一句话总结

> 做游戏不是一次写完，而是：**玩 → 说问题 → 改一点 → 再玩**。  
> 这份 README 里的每一课，都是真实提出过的问题；照着问，就能一步一步做出《雷电风暴》。
